The `country` parameter on [`/v1/web/scrape`](/api-reference/endpoint/web-scraping/scrape)
picks the country your request exits from. The same parameter exists on
`/v1/web/detect`, `/v1/web/screenshot` and `/v1/web/extract`. This page explains
how it behaves and lists which countries had exits on each
[proxy tier](#proxy-tiers) when we last measured.

## How `country` works

- **Any ISO 3166-1 alpha-2 code.** There is no allow-list. The code is passed to
  our residential proxy providers as is, so `"country": "KR"` exits from an IP
  in South Korea.
- **Country-level, not city-level.** The exit's city changes from request to
  request. On the measurement day, `KR` exits were in Seoul, Anseong, Daegu,
  Changwon and other cities. You cannot pick a city.
- **No fallback to another country.** If no exit is available in the country
  you asked for (for example `KP`), the scrape fails instead of going out from
  somewhere else. `/v1/web/scrape` returns HTTP `200` with `success: false` and
  `error: "fetch_failed"`. Failed requests are **not billed**.
- **Default.** Without `country`, requests exit from the US.
- **Per-host overrides.** A host with a
  [per-host override](/api-reference/endpoint/web-scraping/scrape#per-host-overrides-and-automatic-unblocking)
  that pins a country uses the override's country instead of yours.

## Proxy tiers

`proxy_tier` picks the pool the exit comes from. Its surcharge is added to every
request on top of the engine cost. See
[Credit costs](/api-reference/endpoint/web-scraping/scrape#credit-costs).

| Tier | Pool | Surcharge |
|------|------|-----------|
| `simple` (default) | Standard shared pool. The cheapest, with the fewest guarantees about IP type and reputation. | +1 credit |
| `premium` | Residential IPs | +3 credits |
| `ultra` | Residential IPs from our highest-trust providers | +8 credits |

Coverage differs slightly between tiers. Check the tables below before you pick
a tier for a small country.

## Coverage on 2026-11-10

We sent one request per country and tier through `/v1/web/scrape` to an IP
geolocation service (ipinfo.io), retrying once on failure. A tier counts as
covered when the exit IP geolocated in the requested country.

- **232** country codes tested: ISO 3166-1 alpha-2, plus `XK` for Kosovo.
- **215** had an exit in the requested country on at least one tier.
- **205** had an exit on all three tiers.

<Warning>
  This is a snapshot, not a guarantee. Providers add and drop exits, so coverage
  changes over time. If a country matters to you, check it yourself: scrape an
  IP geolocation page with the same `country` and `proxy_tier`, and compare the
  country it reports.
</Warning>

## Other endpoints

[ChatGPT](/api-reference/endpoint/chatgpt/ask) and
[Gemini](/api-reference/endpoint/gemini/ask) asks also use `country` as the exit
country, with exits from the same providers. They were not measured
separately. A country with no exit fails there with `502` and is not billed.

Google AI Mode's `gl` is different. It sets Google's market, not the exit
country. See
[Google AI Mode search](/api-reference/google/google-ai-mode/google-ai-mode-search#country-and-language).

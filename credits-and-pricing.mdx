## Credit Costs by Endpoint

### Web Scraping

| Component | Cost |
|-----------|------|
| Scrape — `http` engine (default) | 1 credit |
| Scrape — `browser` engine (JS rendering) | 5 credits |
| Scrape — proxy tier `simple` / `premium` / `ultra`, added to every scrape | +1 / +3 / +8 credits |
| Scrape — Anti-bot solver add-on | +5 credits |
| Scrape — AI extraction add-on | +2 credits |
| Detect | 1 credit |

<Tip>
  Web scraping retries are free — you only pay for the engine that produces the final result. Failed requests cost 0 credits.
</Tip>

### Twitter

| Category | Endpoints | Cost |
|----------|-----------|------|
| Tweets | 11 endpoints | 1 base credit + 1 credit per item returned |
| Users | 11 endpoints | 1 base credit + 1 credit per item returned |
| Lists | 3 endpoints | 1 base credit + 1 credit per item returned |
| Communities | 3 endpoints | 1 base credit + 1 credit per item returned |
| Trends | 2 endpoints | 1 base credit + 1 credit per item returned |
| Geo | 2 endpoints | 1 base credit + 1 credit per item returned |
| Spaces | 2 endpoints | 1 base credit + 1 credit per item returned |

<Info>
  **Twitter/X is billed per item.** Each request costs **1 base credit plus 1 credit for every item** (tweet, user, etc.) in the response — so a request that returns N items costs **N + 1** credits. For example, an `advanced_search` call returning 20 tweets costs **21 credits**. The exact amount charged for any request is returned in the **`X-Credits-Used`** response header.
</Info>

<Info>
  Failed requests (4xx/5xx errors) do not consume credits. You are only charged for successful responses.
</Info>

## Every request is fresh

ScrapeBadger does not cache responses. Every call fetches fresh data from the source and is billed as normal, even if you sent the identical request a few seconds earlier.

- Two identical requests are two billed requests. If your code retries in a loop, or the same job runs twice, both calls are charged.
- Responses are not stored after they are delivered, so there is no endpoint to re-read an earlier result. To get less data back, narrow the call itself with the [`_jq`, `_fields` and `_max_items` views](/ai-agents#keep-large-results-small).
- Results of [asynchronous calls, batches and webhooks](/long-running-requests) are held in memory only, never written to disk, for at most 15 minutes so you can collect them.

## FAQ

<AccordionGroup>
  <Accordion title="What are credits?">
    Credits are the unit of measurement for API usage. Each API call consumes a certain number of credits based on the endpoint.
  </Accordion>
  <Accordion title="Do credits expire?">
    No, credits never expire. Once purchased, they remain in your account until you use them.
  </Accordion>
  <Accordion title="What happens when I run out of credits?">
    When your credit balance reaches zero, API requests will return a 402 Payment Required error. You can purchase more credits at any time.
  </Accordion>
  <Accordion title="Do you offer refunds?">
    Credits are non-refundable once purchased. However, if you experience technical issues, contact support and we will work with you.
  </Accordion>
  <Accordion title="Am I charged for repeating the same request?">
    Yes. ScrapeBadger does not cache responses, so every call, including an identical repeat, fetches fresh data and is billed as normal. See [Every request is fresh](#every-request-is-fresh).
  </Accordion>
  <Accordion title="Are there volume discounts?">
    Yes! Our larger credit packages offer significant discounts. Check the [pricing page](https://scrapebadger.com/pricing) for current rates.
  </Accordion>
</AccordionGroup>

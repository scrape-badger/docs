  **The `num` parameter is deprecated.** Google no longer honours `num` to widen a page — a single request returns roughly **10 organic results per page**, regardless of the value you pass. To collect more results, paginate with the **`start`** offset (`start=0`, `10`, `20`, …) and merge the pages client-side.
</Warning>

## Search pricing

Regular Search costs **20 credits** per successful uncached request.
[Google Light Search](/api-reference/endpoint/google/light-search) has a dedicated
`/v1/google/light/search` endpoint and costs **10 credits** for organic results
and related searches. No `mode` parameter is required on the Light endpoint.

Legacy `/search?mode=fast` requests remain compatible at the regular route's
20-credit price. Move to `/light/search` for the 10-credit rate.

## Google redirect links

Search attempts to resolve every organic result URL within one short lookup
budget, without waiting for Google's verification timers. If Google delays a
link or changes its response, that link can remain a `google.com/goto` redirect.
Rich-feature links can also remain redirects.

Every result keeps its position. Treat a Google redirect as an unresolved
destination when tracking rankings; do not count `google.com` as the ranking
website. This policy applies to full Search, `mode=fast` and Light Search.

## People Also Ask answers

Google loads each People Also Ask answer only when the question is clicked, so a
plain search returns the questions without answers. Pass
`expand_related_questions=true` to open every question the page shows (usually
four), or a number such as `expand_related_questions=2` to open the first N.
Each answered question in `related_questions` then carries:

- `text_blocks`: the AI-written answer Google shows, as `paragraph`, `heading`
  and `list` blocks, in the same shape as `ai_overview.text_blocks`.
- `references`: the answer's sources, with `title`, `link`, `snippet` and
  `source`. A block's `reference_indexes` are positions in this list.

The answers are fetched during the same search, because Google answers a question
only for the session that loaded the page. There is no token to expand a question
later. A question whose answer did not come back keeps `text_blocks` and
`references` as `null`; retry the search to get it. The search adds about a
second per opened question, and the parameter implies `mode=full`.

Each answered question is billed as one more regular Search request (20 credits
today). A question that does not come back is not billed.

```bash
curl "https://scrapebadger.com/v1/google/search?q=are+noise+cancelling+headphones+worth+it&gl=us&hl=en&expand_related_questions=2" \
  -H "x-api-key: YOUR_API_KEY"
```

## Fast search timeout

With `mode=fast`, search has a 12-second processing budget shared by fetching, retries, fallback and parsing. If no result is ready within that budget, the API returns `503` with `Retry-After: 60`. Wait at least 60 seconds before retrying. Network transit and gateway processing can add to the time you observe.

This budget also applies to `/v1/google/light/search`. The dedicated Light endpoint cannot enable rich SERP features through `mode=full` or `ai_overview=true`. The budget does not apply to regular full Search.

## Location and request controls

`location` resolves a Google canonical location and sends its UULE value to Google.
For example, `New York, USA` resolves to `New York,New York,United States`.
You can also pass a Google geo target criteria ID. Use a complete canonical name
when a short name is ambiguous; a `422` response includes candidate names.

Choose one targeting method:

- `location`: a named location, such as `New York,New York,United States`.
- `uule`: an already encoded Google location. Preserve the `+` by URL encoding it.
- `lat` and `lon`: latitude and longitude, supplied together.

`radius` specifies location accuracy in meters, with coordinates or a named city
whose center is known. It is a location bias, not a geographic boundary around
results. The range is 1–199 meters for desktop and 1–1,000 for other devices.
For a location without an unambiguous center, supply `lat` and `lon` instead.

`gl` sets the country preference; `hl` sets the interface language. Neither is a
city location or a guarantee of the proxy exit country. If `gl` is omitted, a
resolved location supplies the country, then the `domain` country hint, then `us`.
`google_domain` is an alias for `domain`. Requests use `www.google.com` with the
resolved country preference; the response shows the actual request URL.

Both Search and Light accept `color_scheme=light|dark`, `no_cache=true`, and the
advanced Google controls `as_dt`, `as_epq`, `as_eq`, `as_lq`, `as_nlo`, `as_nhi`,
`as_oq`, `as_q`, `as_qdr`, `as_rq`, and `as_sitesearch`. Google may change or stop
honoring individual advanced operators. `no_cache=true` bypasses all response
cache layers; each successful fresh request is billed normally.

Full Search accepts `udm=14` (web) and `udm=18` (forums) for parsed JSON. Other
`udm` values and `tbm=isch|lcl|vid|nws|shop|pts|bks` require `output=html`.
Use the dedicated Google APIs for parsed vertical results. `tbm` and `udm` are
mutually exclusive. Light supports web results only.

```bash
curl --get 'https://scrapebadger.com/v1/google/search' \
  -H 'x-api-key: YOUR_API_KEY' \
  --data-urlencode 'q=vinted api' \
  --data-urlencode 'location=New York,New York,United States' \
  --data-urlencode 'gl=us' \
  --data-urlencode 'hl=en' \
  --data-urlencode 'no_cache=true'
```

### Diagnose differing rankings

`search_parameters` records `location_requested`, `location_resolved`,
`gl_requested`, `domain_requested`, and `google_parameters` from the actual
request URL. A resolved location means it was encoded and sent; it does not prove
Google used that location.

`search_metadata` includes the fetch source and an opaque `session_fingerprint`
when the upstream session is known. Unknown observed location and exit country
remain `null`. No cookies, proxy credentials, slot IDs, or IPs are exposed.
If organic results came from a second fallback page, `organic_results_url`
and `mixed_sources` identify that situation. Cache hits retain the original
fetch diagnostics; inspect `X-Cache` and `Age` for cache status.

Matching query, location, language, country, device, and time reduces differences
between runs. Google can still vary rankings between sessions. For a fresh
comparison, use `no_cache=true`; a fingerprint is a correlation hint and cannot
be used to select or replay a session.

## Google request fields

Search sends `oq=q`, `sourceid=chrome`, and `ie=UTF-8` by default. Override them with the same-named parameters. An explicit empty string omits that field from the Google request. These are Google query parameters; `sourceid` does not change the browser User-Agent, and `ie` is an encoding hint.

<ParamField query="oq" type="string">
  Original query sent to Google. Defaults to q; an empty string omits it.
</ParamField>

<ParamField query="sourceid" type="string" default="chrome">
  Google source identifier. Defaults to chrome; an empty string omits it.
</ParamField>

<ParamField query="ie" type="string" default="UTF-8">
  Google input encoding hint. Defaults to UTF-8; an empty string omits it.
</ParamField>

The `udm=web` alias is accepted and sent to Google as `udm=14`. Inspect `search_parameters.google_parameters` to see the actual request. Matching these fields does not guarantee identical rankings across separate sessions.

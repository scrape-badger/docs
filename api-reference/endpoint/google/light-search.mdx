title: "Google Light Search"
openapi: "GET /v1/google/light/search"
description: "Organic results and related searches through a dedicated lightweight endpoint."
---

A successful uncached request costs **10 credits**. Failed requests and cache
hits are free. Check `X-Credits-Used` for the actual charge and
`/api/public/pricing` for current prices and promotions.

```bash
curl --get 'https://scrapebadger.com/v1/google/light/search' \
  --header 'X-API-Key: YOUR_API_KEY' \
  --data-urlencode 'q=vinted api' \
  --data-urlencode 'gl=us' \
  --data-urlencode 'hl=en'
```

The JSON response contains `search_information`, `organic_results`,
`related_searches` and `pagination`. Light skips ads, AI Overviews, Knowledge
Graph, People Also Ask, local results, news, inline videos and shopping.
No `mode` parameter is required. Passing `mode=full` or `ai_overview=true`
cannot enable rich SERP features.

Use `start=10`, `20`, and so on for later pages. Google may return fewer results
than requested by `num`; a page commonly contains about ten organic results.
Set `output=html` to receive the raw Google response instead of parsed JSON.

`search_information.organic_results_state` is `Results for exact spelling`, `Results for spelling correction` (Google showed results for a corrected spelling), `Results with suggested correction` (Google suggested a spelling with "Did you mean" but kept your query) or `no_results`. `total_results` and `time_taken` are filled only when Google prints them. Light usually gets Google's basic page, which shows no result count or search time, so both are often `null` on Light. Use [regular Search](/api-reference/google/google-search/google-web-search) when you need them.

Light attempts to resolve every organic result URL within one short lookup
budget, without waiting for Google's verification timers. If Google delays a
link or changes its response, that link can remain a `google.com/goto` redirect.
Every result keeps its position. Treat a redirect as an unresolved destination
when tracking rankings; do not count `google.com` as the ranking website.

Light has a 12-second processing budget, including fetching, fallback and
parsing. If the budget expires, the response is `503` with `Retry-After`.

The CLI command is `scrapebadger google light-search "vinted api"`. The MCP tool
is `google_light_search`, with `start` for pagination.

See the [Light overview](/google-light/overview) or
[regular Search](/api-reference/google/google-search/google-web-search).

## Location and fresh requests

Light resolves `location` into Google UULE, like full Search. It also accepts
`uule`, paired `lat`/`lon`, `radius`, `color_scheme`, advanced `as_*` filters, and
`no_cache=true`. Its response includes `search_parameters` and `search_metadata`
to distinguish requested targeting from observed fetch details.

See [location and request controls](/api-reference/google/google-search/google-web-search#location-and-request-controls)
for validation rules and examples. Light remains a web-only API and cannot enable
other search types or rich result blocks.

## Google request fields

Search sends `oq=q`, `sourceid=chrome`, and `ie=UTF-8` by default. Override them with the same-named parameters. An explicit empty string omits that field from the Google request. These are Google query parameters; `sourceid` does not change the browser User-Agent, and `ie` is an encoding hint.

<ParamField query="oq" type="string">
  Original query sent to Google. Defaults to q; an empty string omits it.
</ParamField>

<ParamField query="sourceid" type="string" default="chrome">
  Google source identifier. Defaults to chrome; an empty string omits it.
</ParamField>

<ParamField query="ie" type="string" default="UTF-8">
  Google input encoding hint. Defaults to UTF-8; an empty string omits it.
</ParamField>

The `udm=web` alias is accepted and sent to Google as `udm=14`. Inspect `search_parameters.google_parameters` to see the actual request. Matching these fields does not guarantee identical rankings across separate sessions.

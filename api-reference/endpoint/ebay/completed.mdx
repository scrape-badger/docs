---
title: "Completed / Sold Listings"
openapi: "GET /v1/ebay/completed"
description: "Search eBay completed (sold) listings — the closing prices buyers actually paid."
---

The completed-listings endpoint returns **sold** items — the closing prices buyers
actually paid, with the date each item sold. Every result has `sold` set to `true`
on the response envelope. This is the data resellers, flippers and pricing tools
rely on, since asking prices alone don't reflect what items actually sell for.

Search by keywords, by seller, or both. With `seller` and no `query` you get
everything that seller sold.

## Query Parameters

<ParamField query="query" type="string">
  Search keywords. Matches against listing titles. Optional when `seller` is
  set; send at least one of the two.
</ParamField>

<ParamField query="seller" type="string">
  Only this seller's sold listings, by eBay username (e.g. `musicmagpie`). Works
  on its own, with no keyword, and combines with `query` and every other filter.
</ParamField>

<ParamField query="domain" type="string" default="com">
  eBay marketplace domain TLD or alias. See [`/v1/ebay/markets`](/api-reference/endpoint/ebay/list-markets) for all supported values.

  Examples: `com`, `co.uk`, `de`, `fr`, `com.au`
</ParamField>

<ParamField query="category_id" type="string">
  Restrict results to an eBay category id. Use [`/v1/ebay/categories`](/api-reference/endpoint/ebay/list-categories) to look up ids.
</ParamField>

<ParamField query="page" type="integer" default={1}>
  Page number for paginated results. Range: `1` - `100`.

  Use `pagination.has_more` to know when to stop — eBay re-serves its last
  page if you ask past the end, so this API returns an empty page there.
</ParamField>

<ParamField query="per_page" type="integer">
  Results per page. Clamped to one of `60`, `120`, or `240`. eBay puts at most
  200 sold listings on a page, so `240` returns 200 and `pagination.per_page`
  says `200`; `pagination.returned` says how many this page holds.
</ParamField>

<ParamField query="sort_by" type="string" default="best_match">
  Sort order for results. On sold listings eBay applies only the price sorts.

  | Value | Description |
  |-------|-------------|
  | `best_match` | Newest `ended_at` first (default) |
  | `ending_soonest` | Same order as `best_match`: eBay ignores it on sold listings |
  | `newly_listed` | Same order as `best_match`: eBay ignores it on sold listings |
  | `price_low_to_high` | Lowest sold price first |
  | `price_high_to_low` | Highest sold price first |
</ParamField>

<ParamField query="condition" type="string">
  Item condition filter (`new`, `open_box`, `refurbished`, `used`, `for_parts`).

  Trading cards also accept `graded` and `ungraded` — eBay's card conditions for
  slabbed (PSA / BGS / CGC) versus raw cards. Pricing a raw card against sales
  that include slabs skews the average badly, so price the two separately.
</ParamField>
<ParamField query="location" type="string">
  Item location.

  | Value | Description |
  |-------|-------------|
  | `domestic` | Only items located in this marketplace's own country (`domain=fr` → France only) |
  | `worldwide` | Items from every country |

  Omit it and you get eBay's default, which mixes foreign listings into a national
  marketplace. Two things follow from that, and both matter for price research:
  a national price series picks up sales that never happened in that country, and
  a foreign listing's price is shown **converted** into the marketplace's currency
  rather than the amount it actually sold for. `location=domestic` removes both.

  Any other value returns `400 invalid_location` — it is never silently ignored.
</ParamField>


<ParamField query="min_price" type="number">
  Minimum sold-price filter in the marketplace's local currency.
</ParamField>

<ParamField query="max_price" type="number">
  Maximum sold-price filter in the marketplace's local currency.
</ParamField>

## Response

Identical shape to [`/v1/ebay/search`](/api-reference/endpoint/ebay/search), except `sold` is `true`, each result's `price` reflects the **final sold price**, and each result carries a `sold_date`.

<ResponseField name="query" type="string">The search query that was executed.</ResponseField>
<ResponseField name="domain" type="string">Marketplace domain that was searched.</ResponseField>
<ResponseField name="sold" type="boolean">Always `true` for completed/sold listings.</ResponseField>
<ResponseField name="results" type="array">
  Array of sold listings (same `SearchResult` shape as active search).

  <Expandable title="SearchResult object">
    <ResponseField name="position" type="integer">Position on the page (1-based).</ResponseField>
    <ResponseField name="item_id" type="string">eBay listing item id.</ResponseField>
    <ResponseField name="title" type="string">Listing title.</ResponseField>
    <ResponseField name="url" type="string">Full URL to the listing.</ResponseField>
    <ResponseField name="image" type="string">Primary image URL.</ResponseField>
    <ResponseField name="price" type="object">Final **sold** price with `value`, `currency`, `symbol`, `raw`.</ResponseField>
    <ResponseField name="condition" type="string">Item condition label.</ResponseField>
    <ResponseField name="buying_format" type="string">`Buy It Now`, `Auction`, or `Best Offer`.</ResponseField>
    <ResponseField name="is_auction" type="boolean">Whether the listing was an auction.</ResponseField>
    <ResponseField name="bids" type="integer">Number of bids the auction received (nullable).</ResponseField>
    <ResponseField name="current_bid" type="object">Winning bid for auction listings with `value`, `currency`, `symbol`, `raw`; mirrors `price`. Null for fixed-price listings.</ResponseField>
    <ResponseField name="shipping" type="string">Shipping text.</ResponseField>
    <ResponseField name="location" type="string">Item location text.</ResponseField>
    <ResponseField name="sold_date" type="string">Sale date text as rendered by eBay, e.g. `Aug 19, 2026`. Localized on non-English marketplaces (e.g. `Verkauft 5. Okt. 2024`), nullable.</ResponseField>
    <ResponseField name="sold_date_at" type="string">ISO date of eBay's "Sold" label, e.g. `2026-08-19`: a day the item sold, on the marketplace's calendar. On a multi-quantity listing eBay labels an earlier sale, months before `ended_at` at times. On non-English marketplaces it is the day `ended_at` falls on in Europe/Berlin.</ResponseField>
    <ResponseField name="ended_at" type="string">When eBay last closed this listing out, in UTC to the minute, e.g. `2026-08-19T14:31:00Z`: the listing's end, or the latest sale on a multi-quantity listing that is still live. Results are ordered by it, newest first.</ResponseField>
    <ResponseField name="seller_name" type="string">Seller username (nullable).</ResponseField>
    <ResponseField name="is_sponsored" type="boolean">Always `null`. eBay renders its "Sponsored" badge into every card as anti-scraping bait, so promoted placements cannot be distinguished from organic results.</ResponseField>
  </Expandable>
</ResponseField>
<ResponseField name="facets" type="object">Available filter facets keyed by name.</ResponseField>
<ResponseField name="pagination" type="object">
  Pagination metadata with `current_page`, `per_page`, `total_results`, `has_more`.

  `total_results` is populated (the sold results page carries a match count). `total_pages` may be `null` — page with `has_more` rather than a fixed page total.
</ResponseField>
<ResponseField name="scraped_at" type="string">ISO 8601 timestamp when the results were scraped.</ResponseField>

## Sold listings for one seller

Pass `seller` without a `query` to page through everything one seller sold:

```bash
curl --get 'https://scrapebadger.com/v1/ebay/completed' \
  --data-urlencode 'seller=musicmagpie' \
  --data-urlencode 'domain=co.uk' \
  --data-urlencode 'per_page=200' \
  --header 'x-api-key: YOUR_API_KEY'
```

Every result is one of that seller's sales, and `seller_name` says so. Add
`query`, `category_id`, `condition` or a price range to narrow it down. eBay
handles the request; no eBay account or cookies are needed on your side. How
far back it reaches is eBay's own sold history for that marketplace.

## Fetching every sold listing

`has_more` is the stop signal for bulk extraction. Increment `page` while it is `true`:

```python
page, all_sold = 1, []
while True:
    r = requests.get(
        "https://scrapebadger.com/v1/ebay/completed",
        params={"query": "iphone 13", "per_page": 200, "page": page},
        headers={"X-API-Key": API_KEY},
    ).json()

    all_sold += r["results"]
    if not r["results"] or not r["pagination"]["has_more"]:
        break
    page += 1
```

<Warning>
  Do not loop on "until the response is empty" alone. Past its last page eBay
  **clamps** — asking for page 200 of a 133-page result set re-serves page 133.
  This API detects that and returns an empty page with `has_more: false`, but a
  client that ignores `has_more` and retries forever will keep spending credits.
</Warning>

Pages stop at `100`, so one search returns at most 20,000 listings at `per_page=200`; narrow a bigger result set with `condition`, `category_id` or a price range (`min_price` / `max_price`).
Use the largest `per_page` you can: each request costs 8 credits regardless of page
size, so `per_page=200` is about 3x cheaper per listing than the default.

## Collecting one day's sales

Results come newest `ended_at` first, so one day of a seller's sales is a run of
consecutive pages. To collect a calendar day in your timezone:

1. Convert the day's start and end to UTC (for `Europe/London` on 1 November,
   `2026-11-01T00:00:00Z` to `2026-11-02T00:00:00Z`).
2. Walk `seller=<username>&per_page=200&page=1,2,…`, keeping results whose
   `ended_at` falls inside that window.
3. Stop at the first page whose **last** result has `ended_at` before the
   window's start.
4. De-duplicate on `item_id`.

Things to know before you rely on the count:

- **One result per listing, not per sale.** A multi-quantity listing that sold
  several units appears once, at its latest sale. If it sells again after your
  day, it moves to that later time, so walk soon after the day ends.
- **eBay's sold index is not perfectly consistent.** The same page can come back
  slightly different from one call to the next (one seller's page 1 came back in
  three versions, 217 listings between them, 200 each). A second walk later can
  return a few listings the first missed. Merge walks on `item_id`.
- **The sold history is eBay's.** It covers roughly the last 90 days.

A walk of N pages costs 8 × N credits. Your API key's per-minute limit counts
every `/v1` call, so space a long walk out; a `429` carries a `Retry-After`
header with the seconds to wait.

<Note>
  Each completed/sold request costs **8 credits**. Failed requests are not charged.
</Note>

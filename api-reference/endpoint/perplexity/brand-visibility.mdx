description: "Ask Perplexity a question and get an AEO/GEO analysis of how your brand appears in the answer: mentions, position, share of voice against competitors, and whether your domain was cited."

Ask **the real `perplexity.ai`** a buyer-intent question and get back both the
answer **and** how your brand fares in it: whether it was mentioned, how early,
how often, how it compares to named competitors, and whether your domain was
cited as a source.

Accepts `GET` (query params) or `POST` (JSON body).

**Credits:** 25

<Warning>
  A call can take up to about 75 s while
  exits are tried, so set your client timeout to at least 90 s.
</Warning>

<Note>
  Repeating an identical request within 60 seconds returns the cached answer at
  0 credits, marked `X-Cache: HIT`. To get a fresh answer every time, for
  example to measure how answers vary, send the `Cache-Control: no-cache`
  header. Each fresh answer is billed. See
  [Bypassing the cache](/credits-and-pricing#bypassing-the-cache).
</Note>

## Authorization

<ParamField header="X-API-Key" type="string" required>
  Your ScrapeBadger API key.
</ParamField>

<ParamField header="Cache-Control" type="string">
  Optional. Send `no-cache` to skip the 60-second duplicate-request cache and
  get a fresh answer. The request is billed as normal.
</ParamField>

## Query Parameters

<ParamField query="prompt" type="string" required>
  The question to ask, typically a buyer-intent prompt like
  `best web scraping API for e-commerce`. Maximum 4,096 characters.
</ParamField>

<ParamField query="brand" type="string" required>
  The brand name to look for in the answer, e.g. `ScrapeBadger`.
</ParamField>

<ParamField query="domain" type="string">
  Your domain, e.g. `scrapebadger.com`. Used for `cited`, `cited_urls` and
  `citation_rank`.
</ParamField>

<ParamField query="aliases" type="string">
  Alternate spellings that also count as a mention of `brand`.
  **Comma-separated on `GET`; a `string[]` on `POST`.**
</ParamField>

<ParamField query="competitors" type="string">
  Competitor names to measure against, e.g. `Bright Data,Oxylabs,Zyte`.
  **Comma-separated on `GET`; a `string[]` on `POST`.**
</ParamField>

<ParamField query="country" type="string">
  ISO-3166 alpha-2 market, e.g. `US`, `DE`, `JP`. Sets the ask's language and
  timezone (e.g. `DE`: `de-DE`, `Europe/Berlin`). Omit it and the market whose
  exits answer best right now is used.

  The egress is **best-effort**: when that market has no exit left, another one
  carries the ask and the response `country` says which. Set `strict_country`
  to forbid that.
</ParamField>

<ParamField query="strict_country" type="boolean" default="false">
  Answer only from an exit in `country`, never another one. When no exit there
  answers in time the call fails with **`503`** and
  `detail.code = "country_unavailable"`. It is **not billed** (only `2xx`
  responses are). Requires `country` — `400` otherwise. A JSON `boolean` on
  `POST`.
</ParamField>

<ParamField query="location" type="string">
  Where the asker is. Perplexity answers a local question (`best dentist`,
  `popular cafes`, `moving companies`) for this place. Without it, that place
  is the exit's city, which changes from call to call (a `JP` exit can be in
  Hamamatsu one call and Atsugi the next). Set it when you track a local
  prompt, so every sample is about the same place.

  A city from the list below, or `lat,lng` in decimal degrees (up to 8 decimal
  places), e.g. `35.6812,139.7671`. Case does not matter, and spaces and
  underscores count as hyphens: `New York` and `new_york` both mean
  `new-york`. Any other value is a **`400`**, not billed. A JSON `string` on
  `POST`.

  It does not change the egress. `country` still picks the exit and the answer
  language, so pair the two: `country=JP&location=tokyo`. Questions that are
  not local are unaffected.

  <Expandable title="Cities">
    - **Japan:** `tokyo`, `yokohama`, `osaka`, `nagoya`, `sapporo`, `fukuoka`, `kyoto`, `kobe`, `sendai`, `hiroshima`
    - **Asia-Pacific:** `seoul`, `busan`, `taipei`, `hong-kong`, `singapore`, `bangkok`, `hanoi`, `ho-chi-minh-city`, `jakarta`, `kuala-lumpur`, `manila`, `mumbai`, `delhi`, `bangalore`, `sydney`, `melbourne`
    - **Americas:** `new-york`, `los-angeles`, `chicago`, `san-francisco`, `houston`, `miami`, `seattle`, `washington`, `toronto`, `vancouver`, `mexico-city`, `sao-paulo`, `buenos-aires`
    - **Europe:** `london`, `manchester`, `paris`, `berlin`, `munich`, `hamburg`, `frankfurt`, `madrid`, `barcelona`, `rome`, `milan`, `amsterdam`, `brussels`, `vienna`, `zurich`, `lisbon`, `warsaw`, `istanbul`
  </Expandable>
</ParamField>

<ParamField query="focus" type="string" default="web">
  Retrieval focus: `web`, `scholar` (academic sources) or `social`
  (discussions and forums).
</ParamField>

## Example

<CodeGroup>

```bash cURL
curl -G "https://scrapebadger.com/v1/perplexity/brand-visibility" \
  -H "X-API-Key: YOUR_API_KEY" \
  --data-urlencode "prompt=What is the best web scraping API for e-commerce data?" \
  --data-urlencode "brand=ScrapeBadger" \
  --data-urlencode "domain=scrapebadger.com" \
  --data-urlencode "competitors=Bright Data,Oxylabs,Zyte" \
  --data-urlencode "country=US" \
  --max-time 120
```

```python Python
import requests

res = requests.post(
    "https://scrapebadger.com/v1/perplexity/brand-visibility",
    headers={"X-API-Key": "YOUR_API_KEY"},
    json={
        "prompt": "What is the best web scraping API for e-commerce data?",
        "brand": "ScrapeBadger",
        "domain": "scrapebadger.com",
        "competitors": ["Bright Data", "Oxylabs", "Zyte"],
        "country": "DE",
        "strict_country": True,
    },
    timeout=120,
)
data = res.json()
print(data["country"], data["mentioned"], data["share_of_voice_pct"])
```

</CodeGroup>

## Strict country

By default `country` is best-effort, so a market that is short of exits still
gets an answer, from another market. Check the response `country` to see which
one answered. When the market matters more than the answer (local rankings,
per-country visibility tracking), set `strict_country=true`:

```bash
curl -G "https://scrapebadger.com/v1/perplexity/brand-visibility" \
  -H "X-API-Key: YOUR_API_KEY" \
  --data-urlencode "prompt=best electricity provider" \
  --data-urlencode "brand=Octopus Energy" \
  --data-urlencode "country=DE" \
  --data-urlencode "strict_country=true" \
  --max-time 120
```

If no exit in that market answers in time you get a `503`, which is not billed.
Retry later rather than dropping `strict_country`:

```json 503 Response
{
  "detail": {
    "code": "country_unavailable",
    "message": "no DE exit answered in 16 attempts {...}; strict_country never falls back to another country"
  }
}
```

## Location

A local prompt, such as `best dentist`, gets an answer for the asker's city.
Without `location`, that is the exit's city, so the brands named change with
it between calls. Set `location` to track one place:

```bash
curl -G "https://scrapebadger.com/v1/perplexity/brand-visibility" \
  -H "X-API-Key: YOUR_API_KEY" \
  --data-urlencode "prompt=best moving company" \
  --data-urlencode "brand=Sakai Moving Center" \
  --data-urlencode "country=JP" \
  --data-urlencode "location=tokyo" \
  --max-time 120
```

The response carries `location` next to `country`. An unknown city or a
malformed `lat,lng` is a `400`, which is not billed:

```json 400 Response
{
  "detail": "location must be a city (tokyo, osaka, seoul, new-york, london, ...) or 'lat,lng' in decimal degrees"
}
```

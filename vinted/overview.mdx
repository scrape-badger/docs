Search Vinted listings by **text or image**, inspect items and sellers, and compare
sold listings and suggested prices. ScrapeBadger handles mobile authentication and
market routing. You need a ScrapeBadger API key; no Vinted account is required.

separate endpoint, not one of those 76 read operations.

## Quick start

<CodeGroup>
```bash Text search
curl 'https://scrapebadger.com/v1/vinted/search?query=nike&market=nl&per_page=10' \
  -H 'X-API-Key: YOUR_API_KEY'
```

```bash Image search
curl 'https://scrapebadger.com/v1/vinted/search_by_image' \
  -H 'X-API-Key: YOUR_API_KEY' \
  -H 'Content-Type: application/json' \
  -d '{"image_url":"https://example.com/photo.jpg","market":"nl","per_page":10}'
```

```bash Sold comparables
curl 'https://scrapebadger.com/v1/vinted/mobile/sold-comparables' \
  -H 'X-API-Key: YOUR_API_KEY' \
  -H 'Content-Type: application/json' \
  -d '{"market":"fr","parameters":{"catalog_id":"1242","brand_id":"53","status_id":"2"}}'
```
</CodeGroup>

Replace the example image URL with a public JPEG, PNG or WebP photo. The
[image-search guide](/vinted/image-search) covers base64, local files, filters,
pagination, CLI, MCP and SDK usage.

## Choose a market

`market` defaults to `fr`. Supported codes:
`fr`, `de`, `es`, `it`, `nl`, `be`, `pt`, `pl`, `lt`, `cz`, `at`, `sk`, `hu`, `ro`,
`lu`, `fi`, `dk`, `se`, `gb`, `lv`, `hr`, `ee`, `gr`, `ie`, `si`, `us`, `au`.
`uk` is accepted as an alias for `gb`.

[List markets](/api-reference/endpoint/vinted/list-markets) to get their domains,
locales and currency codes. Market selects the catalog region and locale; it does
not restrict the seller's physical country. European markets can contain listings
from sellers across borders. Prices retain the market currency; ScrapeBadger does
not perform currency conversion.

Text search also supports `seller_country` to filter by seller location after
retrieval. Its pagination totals describe the upstream results before that filter,
so a returned page may contain fewer items than requested.

## Filters and pagination

Both text and image search accept `brand_ids`, `catalog_ids`, `status_ids`,
`color_ids`, `size_ids`, `material_ids`, `price_from`, `price_to`, `page` and
`per_page` (1–96). IDs are comma-separated. Discover IDs in the reference endpoints
or operation catalog. `catalog_ids` filters categories before retrieval.

Text search accepts `order`; image search uses visual ranking. For subsequent
pages, reuse `pagination.time` as `time` and keep `search_session_id` consistent.
Image search also requires the same image source on each page. Deduplicate results
by item ID because listings can change while you paginate.

## Response formats and field availability

- Normalized search returns `items`, `pagination` and `market`.
- Read operations return `operation`, `market` and upstream JSON under `data`.
- Listing summaries include prices, URLs, photos, display labels and available
  size/condition information. Labels may be localized.
- `brand_title` can be null when Vinted omits structured brand data. `display_title`
  is a display label; do not treat it as a reliable brand ID.
- Image search supplies no similarity or confidence score.
- Sold comparables are a sample of sold listings, not exhaustive history. Their
  displayed prices are not guaranteed final negotiated sale prices.

## Pricing

| Request | Credits per success |
| --- | ---: |
| Text search | 5 |
| Image search | 10 |
| Item details | 10 |
| Seller profile or wardrobe | 3 |
| Brand search | 3 |
| Colors or conditions | 1 |
| Any `/mobile/{operation}` read | 1 |
| Markets or operation discovery | 0 |

Failed requests are free. Check `X-Credits-Used` for the billed amount and the
[live pricing page](https://scrapebadger.com/vinted-scraper#pricing) for current rates.

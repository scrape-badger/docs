## Scraper API for Instagram

The ScrapeBadger **Instagram API** turns `instagram.com` into a clean JSON feed:
user profiles with their `about`, `related` accounts, `posts`, `videos`,
`reels`, `tagged` and `pinned` media, followers/following, stories and
highlights; media detail with `oembed`, likers, comments, comment replies and
comment likers; hashtag, location and audio feeds; and search (users, hashtags,
places, top, reels, music, autocomplete).

<Info>
  All endpoints are `GET`, live under `https://scrapebadger.com/v1/instagram/*`,
  and authenticate with the `X-API-Key` header. **No Instagram account or
  upstream API key is required** — ScrapeBadger handles authentication, rate
  limiting, TLS fingerprinting and proxy rotation transparently. Credits are
  charged per request (see the table below) and reported on the
  `X-Credits-Used` response header.
</Info>

## Features

- **Profiles** — full public profile by `username`: bio, links, counts,
  verification, business/professional metadata, plus `about` (country, join
  date, former usernames), `related` accounts and paginated `posts`.
- **User media** — `videos`, `reels`, `tagged` and `pinned` media, active
  `stories` and `highlights`.
- **Social graph** — paginated `followers` and `following`, and search within
  a user's followers.
- **Media** — media detail by shortcode `code`, oEmbed, `likers`, paginated
  `comments`, comment `replies` and per-comment `likers`.
- **Hashtags** — hashtag info by `tag`, plus `top`, `recent` and `reels` feeds.
- **Locations** — search, location detail by `pk`, plus `top` and `recent` feeds.
- **Audio** — trending audio, track info and the media using a track.
- **Search** — `users`, `hashtags`, `places`, blended `top`, `reels`, `music`
  and `autocomplete`.

## Endpoints

| Path | Returns |
| ---- | ------- |
| `/users/{username}` | Profile |
| `/users/{username}/about` | "About this account": country, join date, former usernames |
| `/users/{username}/related` | Similar accounts, in the standard list envelope |
| `/users/{username}/posts` | Feed posts, paginated |
| `/users/{username}/videos` | Video posts from the user's feed, paginated |
| `/users/{username}/reels` · `/tagged` | Reels tab · posts the user is tagged in, paginated |
| `/users/{username}/pinned` | Pinned posts |
| `/users/{username}/followers` · `/following` | Social graph, paginated (`order` on followers) |
| `/users/{username}/followers/search` | Followers matching `query` |
| `/users/{username}/stories` · `/highlights` | Active stories · highlight trays |
| `/stories/{story_pk}` · `/highlights/{highlight_pk}` | One story · one highlight |
| `/media/{code}` · `/media/{code}/oembed` | Media detail · oEmbed payload |
| `/media/{code}/likers` | Users who liked the media |
| `/media/{code}/comments` | Top-level comments, paginated |
| `/media/{code}/comments/{comment_id}/replies` · `/likers` | Replies to · likers of a comment |
| `/hashtags/{tag}` · `/top` · `/recent` · `/reels` | Hashtag info · its feeds |
| `/locations/search` | Locations by `query`, or by `lat`/`lng` |
| `/locations/{location_pk}` · `/top` · `/recent` | Location detail · its feeds |
| `/audio/trending` · `/audio/{audio_id}` · `/audio/{audio_id}/media` | Trending audio · track info · media using the track |
| `/search/users` · `/hashtags` · `/places` · `/top` · `/reels` · `/music` · `/autocomplete` | Search by `query` |

- **`/users/{username}/videos`** pages the user's main feed and keeps the video
  posts, so a page can hold slightly more than `amount` items; pass
  `next_cursor` back as `cursor` to continue the feed.
- **`/search/places`** takes optional `lat` and `lng` to bias the ranking
  toward a point; without them the ranking is global.

## Honesty caveat

<Warning>
  These endpoints read Instagram's **public** surface only. Private accounts
  expose profile metadata but not their posts or media. Fields
  reflect what Instagram serves; some
  professional/business fields are only present when the account has opted into
  them.
</Warning>

## Conventions

- **Pagination.** List endpoints take `amount` (page size) and a `cursor`
  (opaque next-page token). Every list response is wrapped in
  `{ items, count, next_cursor, has_more }` —
  pass `next_cursor` back as `cursor` to walk forward until `has_more` is
  `false`. Pass it back **unchanged**: it identifies the session that served the
  page, because Instagram's own cursors only continue on that session.
- **Page sizes.** `amount` is a target. Hashtag feeds and `/videos` return
  whole Instagram pages, so a page can hold a few more items than `amount`;
  nothing is skipped between pages.
- **Followers.** Instagram shows a viewer only about the first 50 followers of
  another account, so `/followers` stops there with `has_more: false`.
  `/following` pages through the full list.
- **Datetimes.** Every datetime ships in **both** a Unix form (`*_utc`) and an
  ISO 8601 UTC string (`*_at`), e.g. `taken_at` + `taken_at_utc`.

## Quickstart

<CodeGroup>

```bash cURL
curl "https://scrapebadger.com/v1/instagram/users/instagram" \
  -H "X-API-Key: YOUR_API_KEY"
```

```javascript Node.js
const res = await fetch(
  "https://scrapebadger.com/v1/instagram/users/instagram",
  { headers: { "X-API-Key": process.env.SCRAPEBADGER_API_KEY } },
);
const { user } = await res.json();
console.log(user.follower_count, "followers");
```

```python Python
import requests

res = requests.get(
    "https://scrapebadger.com/v1/instagram/users/instagram",
    headers={"X-API-Key": "YOUR_API_KEY"},
)
print(res.json()["user"]["follower_count"], "followers")
```

</CodeGroup>

<Tip>
  Resolve a handle with [`/users/{username}`](/api-reference/endpoint/instagram/get-user),
  then page their media with
  [`/users/{username}/posts`](/api-reference/endpoint/instagram/user-posts) by
  passing the returned `next_cursor` back as `cursor` until `has_more` is false.
</Tip>
